# 远程节点

把一台 Linux 机器接成 DeepSeek Harness 的工作区：**大脑留在那台机器上**，它的工作区和会话直接混排进本地侧栏，点开就用，和本地工作区没有区别。

## 为什么是「远端大脑」而不是「本地代理」

如果本地大脑发指令、远端只执行，那么工具调用要经过路径翻译、argv 改写、可执行文件解析、shell 方言判断——这正是远程工具大面积报 `code=127` 的原因，而且 MCP 服务器、skills、沙箱都无法真正延伸到远端。

所以这里反过来：每个节点自己跑一个完整的 Harness，`bash`、`grep`、`git`、`read_image`、PTY、MCP、skills 全部在那台机器自己的进程里执行，用它的文件系统和它的二进制。本地只是**调度者**：维持一条 SSH 连接，把按 Session / Workspace 寻址的接口路由到该节点，并把它的工作区并进本地那一份 `workspace/follow` 流。

## 怎么用

1. 打开 **设置 › 远程节点**（或侧栏的远程节点面板），在「远程」一栏点 **添加节点**。
2. 填写名称、主机、端口、用户名，选择认证方式（密码或私钥）。
3. 点 **保存**，回到节点行，点 **连接**。插件会探测机器、按需安装同版本 Harness、启动它，并验证会话通道后才报成功。
4. 节点连上后，展开该节点，填一个它上面的绝对路径（例如 `/root/project`），点 **加入工作区**。
5. 回到侧栏：这个远程工作区已经和本地工作区排在一起，点开新建会话、发消息即可。

## 它做了什么

- **一条 SSH 连接**：只需要节点的 22 端口，不开放任何端口、不做端口转发配置；远端宿主只监听它自己的 loopback，所有 HTTP 与 WebSocket 都骑在 SSH 的 `direct-tcpip` 通道上。
- **工作区混排**：`workspace/follow` 变成一份合并流——本机的加上每个已连接节点的，路径是节点上的真实路径（`/root/project`，不是本地镜像目录）。
- **会话混排**：远程 Session 以 `fleet_<节点>_<会话>` 的身份出现在 `session/list` 里，带真实 cwd、标题、投影。所以新建、发消息、取消、改名、fork、翻历史、跟实时流都能用。
- **文件读取走节点磁盘**：`workspaceFiles/*` 先在节点上解析这个 Session，再在节点上读，所以文件查看器和资源系统不用改。
- **手机上也能看到**：因为这些会话是 `session/list` 里真实的行，`ds-harness-remote` 会照常转发给手机，不需要改它一行代码。
- **本地零侵入**：不替换任何上游 Loader 行，不从 `app.asar` 里 import 任何东西。接法是运行时的三处缝隙：在实例上装 own property（Gateway 在 dispatch 时用 `Reflect.get` 取值，在 discovery 时只读类原型，所以覆写生效而声明面不变）、覆写 `workspaceFileScope` lookup（本地 id 原样委托给上游 provider）、以及一个 `/fleet/api` 管理面。

## 限制

- 节点需要 Node.js 22 或更新版本（带 npm）。更老的机器连接时会给出明确提示。
- 每个节点在远端占用约 400 MB 磁盘（Harness 依赖），首次安装需要能访问 npm。
- 本地目录选择器只能浏览**本机**，所以选不到节点上的 `/root/project`：远程工作区要在节点面板里按路径加入。这是有意为之，不是遗漏。
- 会话、工作区与文件都在远端机器上；移除节点不会删除它们。
- 远端 Session 的实时流需要那一轮真的在跑；冷会话打开时先给快照，之后随节点上 Agent 的运行到达事件——和本地行为一致。
